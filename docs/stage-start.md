Работаем по регламенту из https://github.com/mszaitsev/walls-delivery-calc/tree/develop/docs/development-workflow.md

Перед началом:
1. Изучи ТЗ и связанную документацию.
2. Определи влияние задачи на архитектуру.
3. Не пиши код сразу.

Сначала:
- сформулируй решение;
- предложи название ветки;
- подготовь промпт для Codex.

После того как я пришлю результат работы Codex и ссылку на ветку:
- проведи ревью;
- проверь соответствие ТЗ;
- проверь необходимость обновления документации;
- перечисли документы, которые нужно изменить;
- только после этого подтверждай готовность к merge.
