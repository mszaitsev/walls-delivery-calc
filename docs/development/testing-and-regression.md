# Testing And Regression

Version 0.144.1 keeps the PEK shipment smokes in the regression manifest and keeps `ozon-delivery.shipment` plus `ozon-delivery.returns` for Ozon Delivery Shipment Framework integration. The Ozon smokes are fake/local only: they verify typed official endpoint wrappers, `Idempotency-Key` forwarding, actual Shipment modal places and rows, create preflight cost, create+approve, creation-confirmation polling, configurable status mapping, document labels, multi-posting presentation, cancellation polling and partial-cancel reconciliation, human external IDs based on WooCommerce order number, manual attach by existing `posting_number` through official `/v1/posting/info`, no fabricated actual cost for manual attach, and the architecture rule that shipment create does not read checkout Packaging or `ozon_delivery_places`. The order delivery recalculation smoke verifies that selected recalculated pickup rates with trusted `pickup_provider_query` snapshots choose their provider through the registry, including Russian Post to Ozon and Ozon to Russian Post switch regressions. The shipment admin AJAX smoke now performs real metabox render regressions for empty, single, multi, non-Ozon, and malformed return tracking presentations. Automated tests must not call production Ozon APIs.

0.135.11 adds PEK status DateTime regression for the exact production `deliveryPlanDate` value `2026-08-19T22:23:16.833`: the normalizer still accepts the official `/cargos/status/` example `2021-08-19T00:00:00` and the previously supported strict formats, accepts only 3-digit millisecond `Y-m-d\TH:i:s.v` for `deliveryPlanDate`, preserves that original string, rejects other fractional lengths, impossible/fuzzy values, and the same millisecond shape on other status DateTime fields, and still raises `PekShipmentStatusNormalizationException` with safe `field`, `value_type`, and bounded scalar `value` for unsupported status date fields. The architecture guard forbids fuzzy `strtotime()`/generic `DateTimeImmutable` parsing and keeps the millisecond compatibility field-specific.

Safety regressions prove editable mappings do not control PEK cancellation recognition, accepted-cargo protection, already-cancelled reconciliation, or automatic cancelled cleanup.

The plugin architecture smoke is `framework.plugin-architecture`; it is registered in the framework group and checks architecture boundaries rather than carrier business behavior. It favors dynamic Reflection-based checks where the contract is inspectable. Where runtime proof would require changing production construction, the smoke checks a narrower contract instead: registry duplicate behavior is tested with stubs, providers are discovered without uninitialized method calls, and composition-root ownership is checked for the current `Container::register()` wiring pattern.

Allowed matrix values:

- `contract`: shared framework contract smoke.
- `carrier smoke`: required carrier-specific smoke.
- `partial`: covered, but not all variants are represented.
- `baseline`: known failing baseline entry.
- `optional`: optional environment-dependent entry.
- `N/A`: capability does not apply.
